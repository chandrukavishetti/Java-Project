1. Explanation of Design and Implementation


Class Structure: The project follows a modular design.

Model Layer: Includes SudokuBoard (data), SudokuService (business logic/validation), and the Validators (Row, Column, Box).

View/Controller Layer: SudokuPrinter handles UI, InputHandler manages user interaction, and SudokuController orchestrates the game loop and state.

Inheritance: Applied in the InvalidInputException class, which extends the base Java Exception class. This allows us to use standard Java try-catch mechanisms to handle our custom game errors.

Encapsulation: Heavily used in SudokuBoard. The int[][] grid is marked as private and is accessed or modified only through public methods like getValue(), setValue(), and getGrid(). This prevents external classes from corrupting the board state directly.

Static Methods: Used in SudokuGame (the main method). In the game logic, static methods are minimized to promote better object-oriented design and easier testing.

Constructor Chaining: Applied in SudokuBoard. We have a default constructor public SudokuBoard() that could be modified to call a parameterized constructor this(new int[9][9]) to ensure consistent initialization of the grid.

Exception Handling: We handle InvalidInputException across the board:

Format Errors: When users enter characters instead of numbers.

Range Errors: When inputs are outside 1-9.

Game Logic Errors: When a user enters a number that violates Sudoku rules (Row/Column/Box duplicates).
